# Source and licence

This is the `accessibility` skill of [`addyosmani/web-quality-skills`](https://github.com/addyosmani/web-quality-skills), copied verbatim on 2026-11-26 from its folder `skills/accessibility/` at commit `afa8da942115f2961fdbfa80807ea0b232ff6c00`. `skills-lock.json` at the repository root records the source and a hash of the copied files. Its `SKILL.md` frontmatter declares `license: MIT`, and `LICENSE` in this folder is a copy of the upstream repository's MIT licence (copyright 2026 Addy Osmani). It has no scripts, runs nothing when it loads, pre-approves no tool and fetches no remote instructions. Its testing checklist does name commands for the agent to run (`npx lighthouse`, `npm install @axe-core/cli -g`) and Chrome DevTools MCP tools (`lighthouse_audit`, `take_snapshot`); the last point below says what this repository uses instead. Its links are W3C, Deque, WebAIM, TPGi and NV Access pages. The link at the end of `SKILL.md` to `../web-quality-audit/SKILL.md` points to an upstream skill that is not copied here. The same repository's `performance`, `core-web-vitals` and `seo` skills were read and not copied, because most of their advice is already decided, often differently, in docs/08 §10, docs/03 §12.5 and FR-SRCH-005.

It is a WCAG 2.2 audit checklist. DripNepal's target is WCAG 2.2 AA (docs/08 §9), and the skill tracks it closely, so it is a good review aid for storefront and seller pages. It decides nothing: **where it disagrees with the documents, the documents win.** The differences known when it was copied:

- **Large-text contrast is wrong in the skill.** `SKILL.md` gives 3:1 for text of at least 18 px, or 14 px bold, which confuses points with pixels. The threshold is text of at least 24 px, or 18.66 px bold (docs/08 §5.10, `T-UI-003`); below that, text needs 4.5:1. Its example ratios are also off (`#999` on white is about 2.85:1, `#333` on white about 12.6:1); measure, don't copy them.
- **Focus indicator**: a 2 px `--ring` outline with a 2 px offset, and the `focus-visible:border-ring` plus `ring-ring/50` halo that the `ui/` primitives keep (docs/08 §9.1, §5.12). Not the skill's `currentColor` outline or brand box-shadow.
- **Focus not obscured**: `scroll-padding-top` and `scroll-padding-bottom` on the scrolling element, from `--header-h` and `--bottom-bar-h` (docs/08 §6.1 rule 4). Not the skill's fixed `scroll-margin` values.
- **Widgets come from Radix**: dialogs, sheets, tabs, menus and comboboxes are the shadcn/ui primitives, which handle focus and keyboard (docs/08 §4.1, §9.1, §9.2; ADR-0015). Not the skill's hand-written focus trap, native `<dialog>`, `role="dialog"` div, ARIA tabs or `div role="button"` handlers.
- **Form errors and announcements** follow docs/08 §7.1, §7.4 and §11.7: the error summary takes focus when there are two or more errors or the form is long, a single error on a short form moves focus to its field, and focus and announcement are never both used. Live announcements go through the two root live regions and `announce()`; assertive ones are only for session expiry and `RATE_LIMITED`. Not the skill's `role="alert"` on each field error, live region per component or `showNotification()` helper.
- **Accessible names and visible text** come from the string catalogs through `t()` (docs/08 §11.8, `T-UI-022`), not the skill's hard-coded English such as `aria-label="Open menu"` or "(opens in new tab)".
- **Session expiry**: the checkout, product edit and support case forms save a draft (never secrets) to `sessionStorage`, the person signs in again and the draft is restored (docs/08 §7.1); idle limits are enforced by the server per surface, and an idle admin session asks for a new TOTP code (docs/07 §3.4). Not a warning modal with "Extend session".
- **Accessible authentication** (SC 3.3.8): pasting allowed, password managers supported, one TOTP field (docs/08 §9.3). Passkeys, single sign-on and email login links are not scheduled; ADR-0005 only lists passkeys becoming practical as a trigger to revisit the MFA factors.
- **Hidden text, landmarks and colours**: Tailwind's `sr-only`, as the `ui/` primitives use it; `<main id="main" tabindex="-1">` (docs/08 §9.1); colours from the design tokens (docs/08 §5). Not a custom `.visually-hidden` class or hard-coded colours.
- **How it is verified**: axe in Japa's browser suite (`T-A11Y-001`, docs/10), both themes, and the manual release checklist with TalkBack on Android Chrome and NVDA (docs/08 §9.4), with pages checked through the `dripnepal-run` skill. Not `npx lighthouse`, a global `npm install @axe-core/cli` or a Chrome DevTools MCP `lighthouse_audit`: this repository uses pnpm, Lighthouse only reports (`T-PERF-003`, docs/08 §10.1), and installs and browser runs follow the project's own commands.

Its agreements with the documents include the 24 px minimum and 44 px comfortable target sizes (docs/08 §6.4), the reduced-motion rule (docs/08 §5.7), consistent help placement, `<html lang="en">`, and a manual pass because automated tools catch only part of the problems (docs/08 §9.4).
