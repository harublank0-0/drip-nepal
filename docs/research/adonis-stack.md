- [verified-official] In @adonisjs/lucid 22.4.2, db.transaction(callback, options?) is a managed transaction. It commits automatically when the callback resolves and the transaction is still open, and it rolls back and rethrows when the callback throws. db.transaction(options?) with no callback returns a TransactionClientContract that has commit() and rollback().
  - Sources: @adonisjs/lucid 22.4.2 source: build/src/transaction_client/index.js, build/src/types/database.d.ts (TransactionFn) <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; Transactions - Lucid ORM <https://lucid.adonisjs.com/docs/transactions>
  - Implication: Use the callback form for checkout, order split and stock decrement so a thrown error always rolls back. Use the manual form only when you need explicit control.
- [verified-official] Lucid 22.4.2 has the type IsolationLevels = 'read uncommitted' | 'read committed' | 'snapshot' | 'repeatable read' | 'serializable'. It is passed as { isolationLevel } to db.transaction(cb, { isolationLevel }) or db.transaction({ isolationLevel }). The docs say 'snapshot' is MSSQL-only.
  - Sources: @adonisjs/lucid 22.4.2 build/src/types/database.d.ts <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; Transactions - Lucid ORM <https://lucid.adonisjs.com/docs/transactions>
  - Implication: On Postgres 18, keep the default 'read committed' and use row locks for inventory. Use 'serializable' plus retry only for flows that need it, such as payout ledger reconciliation.
- [verified-official] In Lucid 22.4.2, TransactionClientContract has after('commit' | 'rollback', handler) for side effects after commit, plus on/once events. Calling trx.transaction() creates a nested transaction (savepoint), as documented.
  - Sources: @adonisjs/lucid 22.4.2 build/src/types/database.d.ts (TransactionClientContract.after) <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; Transactions - Lucid ORM <https://lucid.adonisjs.com/docs/transactions>
  - Implication: Dispatch order-confirmation emails, SMS and queue jobs in trx.after('commit'), or use an outbox table, so nothing is sent for an order that was rolled back.
- [verified-official] Lucid 22.4.2 has three ways to pass a transaction. ModelAdapterOptions = ModelOptions & { client?: QueryClientContract }, so Model.query({ client: trx }), Model.find(id, { client: trx }) and findBy, first and similar accept a trx. Model instances have $trx and useTransaction(trx). The database, insert, raw and model query builders each have useTransaction(trx). Lucid docs also show User.transaction(cb) (the model's static transaction is typed as TransactionFn).
  - Sources: @adonisjs/lucid 22.4.2 build/src/types/model.d.ts, build/src/orm/query_builder/index.d.ts, build/src/database/query_builder/\*.d.ts <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; Transactions - Lucid ORM <https://lucid.adonisjs.com/docs/transactions>
  - Implication: Doc examples should use `Product.query({ client: trx })` and `order.useTransaction(trx)`. Do not invent `Model.query().transacting()`.
- [verified-official] In Lucid 22.4.2, ChainableContract is extended by both the database query builder and ModelQueryBuilderContract. It exposes forUpdate(...tableNames), forShare(...tableNames), skipLocked() and noWait(). forNoKeyUpdate and forKeyShare are not exposed in the typings; knexQuery is available for raw Knex access. The docs show locks inside db.transaction and say skipLocked and noWait need PostgreSQL 9.5+ or MySQL 8.0+.
  - Sources: @adonisjs/lucid 22.4.2 build/src/types/querybuilder.d.ts lines 514-517, build/src/types/model.d.ts line 247 <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; Select query builder - Lucid ORM <https://lucid.adonisjs.com/docs/select-query-builder>
  - Implication: Stock reservation can use `ProductVariant.query({ client: trx }).where('id', id).forUpdate().firstOrFail()`. Job claiming can use forUpdate().skipLocked(). Always run locks inside a transaction.

The repo's generated database/schema.ts declares price, amount and subtotal as `string`. The Lucid docs say decimal maps to string to preserve exact precision.
  - Sources: @adonisjs/lucid 22.4.2 build/src/orm/schema_generator/rules.js and mappings.js <https://registry.npmjs.org/@adonisjs/lucid/-/lucid-22.4.2.tgz>; drip-nepal generated database/schema.ts `database/schema.ts`; Schema classes (Models) - Lucid ORM <https://lucid.adonisjs.com/docs/schema-classes>
  - Implication: NPR money comes back as a string from decimal(10,2). Either store integer paisa (bigint or integer) or treat decimals as strings and use a decimal library. Never add money values as JS floats. Record this choice in the data-model doc.

- [verified-official] In @adonisjs/auth 10.1.0, SessionGuard.login(user, remember = false) does the following. It throws a RuntimeException if remember is true while useRememberMeTokens is disabled. - [verified-official] @adonisjs/auth 10.1.0 has no built-in option to reject suspended or inactive users. - [partially-verified] In @adonisjs/session 8.1.0, session.regenerate() only assigns a new randomUUID in memory.   - Sources: @adonisjs/session 8.1.0 build/session-CB0uNFzC.js (regenerate, commit), build/database-CuWB6hfN.js (write, tag) <https://registry.npmjs.org/@adonisjs/session/-/session-8.1.0.tgz>
