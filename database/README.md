# Database

The schema is the E4 baseline of [ADR-0011](../docs/adr/0011-schema-rebaseline-before-production.md): 14 migration files that replaced the prototype's schema. The documents own every table, column and constraint; this file only says where things are. Edited 2026-11-09: it described the v1 schema (roles, permissions, carts, orders) that the baseline removed.

## Where the schema is defined

- **Tables, columns, constraints, indexes and triggers:** [docs/04a](../docs/04a-data-dictionary-tables.md). The baseline writes them as its SQL, through `this.schema.raw(…)`.
- **Conventions** (identifiers, money in paisa, enumerations, composite tenant keys, append-only tables, naming): [docs/04 §2](../docs/04-domain-model-and-data-dictionary.md#2-modelling-conventions).
- **The 14 files and their order:** [docs/04 §20.2.2](../docs/04-domain-model-and-data-dictionary.md#2022-baseline-files-and-their-order), from `baseline_extensions_and_functions` to `baseline_grants`, so that every foreign key points at a table created earlier.
- **Migration rules** (naming, one concern per file, expand and contract, never editing an applied file): [docs/09 §8](../docs/09-code-structure-and-engineering-standards.md#8-migrations-and-seeders).

## Roles

The database has three roles, as [docs/07 §4.10](../docs/07-security-threat-model-and-permissions.md#410-database-roles-and-grants) defines them:

- `dripnepal_migrator` owns the schema and runs migrations and reference seeders.
- `dripnepal_app` is what the web and worker processes use: data changes only, with no `UPDATE` or `DELETE` on the append-only tables (granted by `baseline_grants`, `T-ARCH-012`).
- `dripnepal_readonly` gets the incident-read grants, without the secret tables and columns.

Tests run the same way: the run setup migrates as the migrator and the suites connect as `dripnepal_app` ([docs/10 §3.2](../docs/10-testing-and-quality-gates.md#32-the-test-database)). `docker/postgres/init/` creates the roles for local development.
